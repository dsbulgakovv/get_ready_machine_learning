# Metric Tree

## Как читать схему
Дерево метрик показывает, как связать бизнес-результат, продуктовые прокси, offline ML-качество, системные ограничения и decision criteria.

## Что проговорить на интервью
- Business-метрика отвечает на вопрос, принесла ли система деньги, удержание, снижение потерь или качество сервиса.
- Product-метрики обычно реагируют быстрее и помогают диагностировать funnel: CTR, CVR, activation, frequency, complaints.
- ML-метрики должны соответствовать типу задачи: PR-AUC для редких положительных классов, NDCG@K для ranking, WAPE для demand/forecasting.
- Diagnostic metrics нужны для объяснения деградации: freshness, missing rate, drift, score distribution, label delay.
- Решение о запуске принимается не по одной offline-метрике, а по бизнес-эффекту при стабильных guardrails.

## Термины и короткие пояснения

### PR-AUC
Площадь под precision-recall кривой. Особенно полезна при дисбалансе классов, например fraud, churn, abuse.

### NDCG@K
Ranking-метрика, которая учитывает позицию релевантных объектов в top-K и штрафует хорошие ответы, показанные слишком низко.

### WAPE
Weighted Absolute Percentage Error: сумма абсолютных ошибок, деленная на сумму фактических значений. Удобна для demand/revenue forecasting.

### Calibration
Соответствие вероятностей реальной частоте событий. Если модель говорит 0.8, событие должно происходить примерно в 80% таких случаев.
